# Схема `audio_five_band_notch.json`: Строгий Физический Разбор, Работа Каждого Элемента И Анализ Графиков

## 1. Что Это За Схема

Файл:

- `examples/audio_five_band_notch.json`

Это не простой "тихий фильтр", а параллельный многополосный поглотитель частот.

Идея схемы такая:

- входной аудиосигнал приходит на узел выхода через входной резистор;
- от этого узла на землю висят пять последовательных `L-C` веток;
- каждая ветка на своей резонансной частоте становится низкоомным шунтом;
- в эти моменты соответствующая полоса сигнала не проходит дальше на выход, а "утекает" в землю через резонансную ветвь.

Именно поэтому это именно `notch / suppression`, а не `band-pass`:

- схема не выделяет нужные полосы;
- она проваливает выбранные полосы;
- остальной сигнал проходит лучше, чем резонансные точки.

## 2. Топология Схемы

Полный тракт:

```text
AudioFileSource
-> R_IN
-> узел J_OUT
-> пять параллельных ветвей {L_NOTCH_i -> C_NOTCH_i -> GND}
-> C_TOP_SHAVE -> GND
-> AudioSink
```

По JSON:

- `SRC_AUDIO` - входной аудиоисточник
- `R_IN` - входной последовательный резистор
- `J_OUT` - общий выходной узел
- `L_NOTCH_1 ... L_NOTCH_5` - пять индуктивностей notch-ветвей
- `C_NOTCH_1 ... C_NOTCH_5` - пять конденсаторов notch-ветвей
- `C_TOP_SHAVE` - дополнительный верхний шунтирующий конденсатор
- `OUT_NOTCH` - съем и экспорт результата

Сами компоненты и номиналы см. в [audio_five_band_notch.json](/Users/arturadamov/PycharmProjects/SoyuzOrbit/examples/audio_five_band_notch.json#L17), соединения см. в [audio_five_band_notch.json](/Users/arturadamov/PycharmProjects/SoyuzOrbit/examples/audio_five_band_notch.json#L241).

## 3. Какие Общие Физические Законы Использует Решатель

### 3.1. Закон Кирхгофа По Токам

Для каждого узла выполняется:

```text
sum I_k = 0
```

То есть сумма токов, уходящих из узла, и сумма токов, приходящих в узел, должны балансироваться.

Это основной закон, на котором держится вся схема.

### 3.2. Узловой Нелинейный Расчет

После штамповки всех компонентов система решает:

```text
F(V) = 0
```

итерациями Ньютона:

```text
J(V_n) * dV = -F(V_n)
V_(n+1) = V_n + dV
```

См. [engine.py](/Users/arturadamov/PycharmProjects/SoyuzOrbit/core/engine.py#L370) и [engine.py](/Users/arturadamov/PycharmProjects/SoyuzOrbit/core/engine.py#L435).

### 3.3. Дискретное Время

В `audio_five_band_notch.json` задано:

```text
dt = 62.5 us
sample_rate = 16000 Hz
```

См. [audio_five_band_notch.json](/Users/arturadamov/PycharmProjects/SoyuzOrbit/examples/audio_five_band_notch.json#L4).

Следовательно:

- аудио в схеме подается как временная ЭДС;
- реактивные элементы считаются через дискретные companion-модели;
- поведение фильтра зависит от `dt`, то есть от частоты дискретизации симуляции.

## 4. Разбор Каждого Элемента Схемы

## 4.1. `SRC_AUDIO`: Audio File Source

См. [components.py](/Users/arturadamov/PycharmProjects/SoyuzOrbit/core/components.py#L625).

### Физический смысл

Это эквивалент Теvenin:

```text
идеальная ЭДС e(t) + внутреннее сопротивление R_s
```

В этой схеме:

- `internal_resistance_ohm = 0.2`
- `peak_voltage_v = 1.0`

### Как музыка попадает в схему

Аудиофайл декодируется в массив сэмплов `x[n]`, после чего внутри симуляции берется линейно интерполированное значение:

```text
x(t) = x[n] + (x[n+1] - x[n]) * frac
e(t) = V_dc + V_peak * x(t)
```

См. [components.py](/Users/arturadamov/PycharmProjects/SoyuzOrbit/core/components.py#L710) и [components.py](/Users/arturadamov/PycharmProjects/SoyuzOrbit/core/components.py#L746).

### Закон тока источника

```text
I = (V_branch - e(t)) / R_s
```

или:

```text
G = 1 / R_s
I = G * V_branch - G * e(t)
```

См. [components.py](/Users/arturadamov/PycharmProjects/SoyuzOrbit/core/components.py#L750).

### Практический смысл

Источник не идеален:

- при нагрузке напряжение на схеме может отличаться от идеального `e(t)`;
- сеть резонансных ветвей реально забирает у него ток.

## 4.2. `R_IN`: Входной Последовательный Резистор

См. [components.py](/Users/arturadamov/PycharmProjects/SoyuzOrbit/core/components.py#L42).

### Закон

Обычный закон Ома:

```text
I = V / R(T)
```

С температурной поправкой:

```text
R(T) = R_actual * (1 + alpha * (T - T_ref))
```

См. [components.py](/Users/arturadamov/PycharmProjects/SoyuzOrbit/core/components.py#L67).

### Роль в схеме

`R_IN` критически важен. Он вместе с эквивалентной шунтирующей проводимостью notch-ветвей образует делитель напряжения:

```text
H(jw) = Vout / Vin ~ Z_shunt(jw) / (R_source + R_IN + Z_shunt(jw))
```

Когда шунтирующая часть становится низкоомной, выход падает.

Без `R_IN` резонансные ветви либо слишком жестко нагружали бы источник, либо схема стала бы менее управляемой как фильтр.

## 4.3. Пять Notch-Ветвей Как Класс Элементов

Каждая ветвь имеет вид:

```text
J_OUT -> L_NOTCH_i -> C_NOTCH_i -> GND
```

Это последовательная `L-C` цепочка, подключенная к выходному узлу параллельно остальным ветвям.

### Базовая непрерывная физика

Для индуктора:

```text
V_L = L * dI/dt
lambda = L * I
```

Для конденсатора:

```text
I_C = C * dV/dt
Q = C * V
```

Импедансы в частотной области:

```text
Z_L = j * w * L
Z_C = 1 / (j * w * C)
```

Для последовательной идеальной цепочки:

```text
Z_LC = j*w*L + 1/(j*w*C)
```

На резонансе:

```text
w0 = 1 / sqrt(L * C)
f0 = 1 / (2*pi*sqrt(L*C))
```

В этой точке реактивные части сокращаются:

```text
j*w0*L + 1/(j*w0*C) = 0
```

И ветка становится почти чисто резистивной с минимальным импедансом.

### Почему это дает провал, а не подъем

Потому что ветка сидит не последовательно в тракте, а шунтом на землю.

Следовательно:

- на резонансной частоте она особенно хорошо проводит;
- ток уходит через нее в землю;
- напряжение на `J_OUT` падает;
- на выходе появляется notch-провал.

## 4.4. `L_NOTCH_i`: Индукторы

См. [components.py](/Users/arturadamov/PycharmProjects/SoyuzOrbit/core/components.py#L262).

### Что реализовано в проекте

Это не учебный идеальный `L`, а модель с:

- конечным `dc_resistance_ohm`;
- магнитным током состояния;
- насыщением;
- паразитной межвитковой емкостью;
- тепловой моделью.

### Дискретная модель

В коде индуктивность на шаге `dt` превращается в эквивалент:

```text
G_ind = 1 / (R + L/dt)
I_eq = (L/dt * I_prev) / (R + L/dt)
```

См. [components.py](/Users/arturadamov/PycharmProjects/SoyuzOrbit/core/components.py#L297).

### Очень важная деталь этой схемы

В `RealInductor` есть:

```text
L_eff = L_air * relative_permeability * saturation_factor
```

При малом токе и без насыщения:

```text
L_eff ~ L_air * relative_permeability
```

По умолчанию:

```text
relative_permeability = 25
```

См. [components.py](/Users/arturadamov/PycharmProjects/SoyuzOrbit/core/components.py#L271) и [components.py](/Users/arturadamov/PycharmProjects/SoyuzOrbit/core/components.py#L290).

Это означает, что реальные начальные резонансные частоты здесь примерно в `sqrt(25) = 5` раз ниже, чем если бы ты считал только по числу `inductance_h` из JSON как по "готовой" индуктивности.

Это ключевой момент для интерпретации твоего спектра.

## 4.5. `C_NOTCH_i`: Конденсаторы Ветвей

См. [components.py](/Users/arturadamov/PycharmProjects/SoyuzOrbit/core/components.py#L192).

### Что реализовано

Это реальный конденсатор с:

- `capacitance_f`
- `esr_ohm`
- `esl_h`
- `leak_resistance_ohm`
- `max_voltage_v`

### Дискретная модель

На шаге `dt` строится companion:

```text
G_cap ~ C / dt
I = G_cap * V + I_eq
```

Плюс учитываются:

- ESR
- утечка
- условный breakdown

См. [components.py](/Users/arturadamov/PycharmProjects/SoyuzOrbit/core/components.py#L221) и [components.py](/Users/arturadamov/PycharmProjects/SoyuzOrbit/core/components.py#L230).

### Роль в notch-ветках

Все пять ветвей имеют одинаковую емкость:

```text
C = 4.7 uF
```

Следовательно, частоты полос задаются в основном разными `L_NOTCH_i`.

## 4.6. Частоты Пяти Полос

Если использовать физику именно этой модели, то на малом токе:

```text
L_eff ~ 25 * L_air
```

Тогда приближенные резонансные частоты получаются такими:

1. `L_NOTCH_1 = 6.8 mH` -> `L_eff ~ 0.17 H` -> `f0 ~ 178 Hz`
2. `L_NOTCH_2 = 2.7 mH` -> `L_eff ~ 0.0675 H` -> `f0 ~ 283 Hz`
3. `L_NOTCH_3 = 1.2 mH` -> `L_eff ~ 0.03 H` -> `f0 ~ 424 Hz`
4. `L_NOTCH_4 = 0.47 mH` -> `L_eff ~ 0.01175 H` -> `f0 ~ 677 Hz`
5. `L_NOTCH_5 = 0.2 mH` -> `L_eff ~ 0.005 H` -> `f0 ~ 1038 Hz`

Это объясняет очень важную вещь:

- на твоем спектре до `500 Hz` уже можно ожидать первые три провала;
- четвертая и пятая полоса частично или полностью выходят за пределы показанного диапазона.

То есть эта ветвь выбивает нижнюю из видимых notch-полос.

## 4.7. `C_TOP_SHAVE`: Дополнительный Верхний Шунт

Это еще один `RealCapacitor`, см. [components.py](/Users/arturadamov/PycharmProjects/SoyuzOrbit/core/components.py#L192).

### Физическая роль

Он подключен прямо от `J_OUT` к земле.

Значит:

- при росте частоты его реактивное сопротивление падает;
- очень верхние составляющие получают еще один путь в землю;
- верхний край спектра дополнительно приглаживается.

Это не основной notch-элемент, а верхний "top shave".

## 4.8. `OUT_NOTCH`: Audio Sink

См. [components.py](/Users/arturadamov/PycharmProjects/SoyuzOrbit/core/components.py#L800).

### Электрический смысл

Это почти не нагружающий измерительный порт:

- `input_resistance_ohm = 1e9`
- `input_capacitance_f = 0`

Следовательно, он почти не влияет на сам фильтр.

### Что идет в аудиовыход

Он не пишет ток как звук. Он сохраняет напряжение на своем узле:

```text
reading_v = V_node
captured_v = output_gain * (V_node - running_mean), если dc_block = true
```

В этой схеме:

- `output_gain = 1.75`
- `dc_block = true`

См. [components.py](/Users/arturadamov/PycharmProjects/SoyuzOrbit/core/components.py#L835).

Значит, на аудио-графиках ты смотришь уже не просто "голое напряжение узла", а:

- DC-blocked
- масштабированный выходной сигнал

## 5. Как Вся Схема Работает Целиком

Если свернуть схему в одну инженерную формулу, то картина такая:

```text
Vin -> R_IN -> узел J_OUT
J_OUT шунтируется суммой пяти резонансных ветвей и C_TOP_SHAVE
Vout снимается с J_OUT
```

Эквивалентная шунтирующая проводимость:

```text
Y_shunt(jw) = sum_i 1/Z_notch_i(jw) + j*w*C_top + ...
```

Эквивалентный шунтирующий импеданс:

```text
Z_shunt(jw) = 1 / Y_shunt(jw)
```

И тогда передаточная функция по напряжению в первом приближении:

```text
H(jw) = Z_shunt(jw) / (R_source + R_IN + Z_shunt(jw))
```

Следовательно:

- если `Z_shunt` большой, выход близок к входу;
- если на какой-то частоте одна из ветвей уходит в резонанс и `Z_shunt` падает, выход на этой частоте проседает.

Именно это физически и есть notch-фильтрация.

## 6. Анализ Твоих Графиков

Ниже анализ именно тех картинок, которые ты прислал.

## 6.1. График `Аудио: входное и выходное напряжение`

Что видно:

- вход `Input:SRC_AUDIO` имеет заметно больший размах;
- выход `Output:OUT_NOTCH` намного слабее;
- структура фраз и музыкальных участков сохраняется по времени;
- но амплитуда на выходе существенно подавлена почти по всей записи.

Что это означает:

1. Схема работает как поглощающий фильтр, а не как активный эквалайзер.
Она не усиливает выбранные полосы, а системно ослабляет часть энергии сигнала.

2. Подавление не локальное по времени, а спектральное.
Видно, что выход остается коррелированным с входом по структуре, значит схема не разрушает временную организацию сигнала, а в основном вырезает часть спектрального состава.

3. Ослабление достаточно сильное.
Это говорит о том, что суммарная шунтирующая сеть действительно имеет заметную проводимость в существенной части полезной полосы.

## 6.2. Панель `Токи компонентов`

На присланном графике видно:

- ток источника `SRC_AUDIO` хорошо заметен;
- токи `OUT_NOTCH` и `OUT_NOTCH:входной ток` почти нулевые.

Что из этого следует:

1. Выходной sink почти не нагружает схему.
Это ровно то, что и должно быть при `input_resistance_ohm = 1e9`.

2. Основной ток источника идет не в выходной прибор, а в шунтирующие ветви фильтра.
Это важный физический вывод: энергия не "исчезает магически", а перетекает в резонансные ветви к земле.

3. Этот конкретный график не позволяет различить, какая именно из пяти ветвей активна в конкретный момент.
Для этого надо строить токи `L_NOTCH_1 ... L_NOTCH_5` отдельно.

То есть текущая панель полезна, но только для общего вывода:

```text
sink почти не грузит
источник реально питает фильтр
```

## 6.3. Панель `Напряжения и ЭДС`

На этой картинке видно:

- `SRC_AUDIO` и его ЭДС практически совпадают по смыслу как входной драйв;
- `OUT_NOTCH.reading_v` и `OUT_NOTCH.captured_v` заметно меньше по размаху;
- сигнал после фильтра остается центрированным около нуля.

Что это означает:

1. Узловое напряжение на выходе реально подавлено до пост-обработки.
То есть attenuation появляется в самой схеме, а не создается только на этапе записи файла.

2. `captured_v` и `reading_v` близки, потому что:

- `dc_block = true`, но DC-смещение у сигнала небольшое;
- `output_gain = 1.75`, поэтому выходной файл частично возвращает уровень после фильтра.

3. Видно, что выходная форма значительно "тоньше" по размаху, но остается временно похожей на вход.
Это классическая картина пассивной селективной фильтрации.

## 6.4. График `Аудио: спектр входа и выхода`

Это самый важный график для этой схемы.

Что видно:

- выходной спектр почти по всему видимому диапазону ниже входного;
- заметны особенно глубокие провалы в нескольких областях;
- картинка соответствует не просто общему ослаблению, а многополосному подавлению.

Но здесь есть очень важная оговорка.

На картинке показан диапазон только примерно до `500 Hz`.

Следовательно:

- по ней можно анализировать первые три notch-полосы;
- по ней нельзя полноценно судить о четвертой и пятой полосе, потому что они лежат выше.

### Что уже можно уверенно сказать по этой картинке

1. В диапазоне до `500 Hz` фильтр действительно делает несколько провалов, а не один общий low-pass.

2. Эти провалы физически согласуются с расчетными первыми тремя полосами:

- около `178 Hz`
- около `283 Hz`
- около `424 Hz`

3. То есть схема реально ведет себя как многополосный notch-абсорбер.

### Что по этой картинке сказать нельзя

Нельзя честно утверждать, что "видны все 5 провалов", потому что:

- `f4 ~ 677 Hz`
- `f5 ~ 1038 Hz`

а этот спектральный график обрезан раньше.

Строгий вывод должен звучать именно так:

```text
на присланном спектре видна работа первых трех полос;
полосы 4 и 5 по этим данным не проверяются напрямую
```

## 7. Главный Вывод По Схеме

Физически эта схема работает как пассивный многополосный шунтирующий фильтр.

Цепочка причинности такая:

```text
входной аудиосигнал подается на J_OUT через R_IN
-> каждая LC-ветвь имеет свою резонансную частоту
-> на резонансе ветвь становится низкоомной
-> соответствующая полоса уходит током в землю
-> напряжение на J_OUT для этой полосы падает
-> на выходе возникает notch-провал
```

То есть здесь "гашение волн" физически означает:

- не уничтожение сигнала как объекта;
- а уменьшение напряжения на выходном узле из-за роста шунтирующего тока в выбранных частотных полосах.

## 8. Что На Этих Графиках Имеет Смысл Анализировать

### 8.1. Анализ Полос Подавления

По спектру имеет смысл смотреть:

- глубину провала каждой полосы;
- ширину провала;
- расстояние между полосами;
- насколько вне провалов сигнал сохраняется.

### 8.2. Анализ Энергетики

По связке `токи + напряжения` можно анализировать:

- куда реально уходит энергия;
- насколько источник нагружен;
- насколько output-port сам влияет на схему.

### 8.3. Анализ Временной Сохранности

По входному и выходному напряжению во времени можно смотреть:

- сохраняется ли временная структура речи/музыки;
- не превращает ли схема звук в почти тишину;
- насколько фильтр "жесткий" по общему attenuation.

## 9. Что Важно Улучшить Для Еще Более Строгого Анализа

Если хочешь увидеть именно "все пять волн", а не только общую картину, то полезно строить отдельно:

1. спектр до `1500 Hz`
2. токи `L_NOTCH_1`, `L_NOTCH_2`, `L_NOTCH_3`
3. токи `L_NOTCH_4`, `L_NOTCH_5`, `SRC_AUDIO`
4. напряжение на `J_OUT` и напряжения на промежуточных узлах `J_NOTCH_i`

Тогда будет видно уже совсем строго:

- какая ветвь на какой частоте забирает ток;
- как глубина провала связана с реальным резонансным током.

## 10. Практическая Оговорка

Эта схема физически осмысленна как электрический многополосный шунтирующий фильтр. Но слуховой эффект "чисто/грязно/музыкально" зависит еще и от:

- того, какой входной материал подан;
- где у этого материала основные гармоники;
- как потом это воспринимается ухом.

Поэтому корректнее говорить так:

- проект корректно считает электрическую селективную фильтрацию этого тракта;
- а художественный эффект зависит от того, попадают ли реальные гармоники голоса или музыки в рассчитанные notch-полосы.
