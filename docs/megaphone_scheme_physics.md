# Схема `audio_speech_megaphone_distortion.json`: Строгий Физический Разбор, Работа Каждого Элемента И Анализ Графиков

## 1. Что Это За Схема

Файл:

- `examples/audio_speech_megaphone_distortion.json`

Это не "просто эффект перегруза", а составная речевая схема, которая делает сразу три вещи:

1. вырезает низкие частоты;
2. ограничивает амплитуду асимметрично по положительной и отрицательной полуволне;
3. слегка сглаживает верхнюю часть полосы и затем усиливает результат на выходе.

Именно эта комбинация и дает характер "мегафона" или "громкоговорителя":

- мало баса;
- много середины;
- пики уплощены;
- тембр грубый и узкий.

## 2. Топология Схемы

Цепочка такая:

```text
AudioFileSource
-> C_HP
-> узел J_HP
-> R_DRIVE
-> узел J_CLIP
-> {V_CLIP, D_POS, D_NEG, C_LP, R_LEAK, OUT_MEGA}
-> AudioSink
```

По JSON:

- `SRC_AUDIO` - источник аудио
- `C_HP` - входной разделительный / high-pass конденсатор
- `R_HP_GND` - резистор утечки на землю после `C_HP`
- `R_DRIVE` - сопротивление, задающее ток в клиппирующий узел
- `V_CLIP` - симметричный нелинейный ограничитель
- `D_POS` - более раннее ограничение положительной полуволны
- `D_NEG` - более позднее ограничение отрицательной полуволны
- `C_LP` - шунтирующий верх конденсатор на клип-узле
- `R_LEAK` - медленная утечка узла к земле
- `OUT_MEGA` - измерение и выдача выходного аудио

Смотри номиналы в [audio_speech_megaphone_distortion.json](/Users/arturadamov/PycharmProjects/SoyuzOrbit/examples/audio_speech_megaphone_distortion.json#L17) и соединения в [audio_speech_megaphone_distortion.json](/Users/arturadamov/PycharmProjects/SoyuzOrbit/examples/audio_speech_megaphone_distortion.json#L155).

## 3. Какие Общие Физические Законы Использует Весь Решатель

### 3.1. Закон Кирхгофа По Токам

Для каждого узла схема решается из условия:

```text
sum I_k = 0
```

То есть суммарный ток, втекающий в узел, равен суммарному току, вытекающему из узла.

Это основа всего расчета. Каждый компонент возвращает:

- свой ток как функцию напряжений;
- свою локальную дифференциальную проводимость.

См. базовую реализацию двухполюсника в [component.py](/Users/arturadamov/PycharmProjects/SoyuzOrbit/core/component.py#L104).

### 3.2. Узловой Анализ И Ньютон

Вся схема собирается в нелинейную систему:

```text
F(V) = 0
```

и решается итерационно:

```text
J(V_n) * dV = -F(V_n)
V_(n+1) = V_n + dV
```

Где:

- `V` - вектор узловых напряжений;
- `F` - невязка по токам;
- `J` - матрица Якоби.

См. шаги симуляции в [engine.py](/Users/arturadamov/PycharmProjects/SoyuzOrbit/core/engine.py#L370) и [engine.py](/Users/arturadamov/PycharmProjects/SoyuzOrbit/core/engine.py#L435).

### 3.3. Дискретное Время

Симуляция идет по шагам `dt`.

Для `megaphone` в JSON задано:

```text
dt = 62.5 us
sample_rate = 1 / dt = 16000 Hz
```

См. [audio_speech_megaphone_distortion.json](/Users/arturadamov/PycharmProjects/SoyuzOrbit/examples/audio_speech_megaphone_distortion.json#L4).

Это важно: реактивные элементы здесь считаются не в "идеальном непрерывном мире", а через дискретные companion-модели.

### 3.4. Тепловая Подсистема

Даже если в конкретном `megaphone` тепловой эффект на звук почти не влияет, все элементы имеют общую тепловую модель:

```text
C_j * dT_j/dt = P - (T_j - T_s) / R_js
C_s * dT_s/dt = (T_j - T_s) / R_js - (T_s - T_amb) / R_sa
```

В коде это реализовано в общей форме через `integrate_temperature`, где есть:

- внутренняя температура;
- поверхностная температура;
- теплоемкости;
- тепловые сопротивления.

См. [component.py](/Users/arturadamov/PycharmProjects/SoyuzOrbit/core/component.py#L74).

## 4. Разбор Каждого Элемента Схемы

## 4.1. `SRC_AUDIO`: Audio File Source

См. [components.py](/Users/arturadamov/PycharmProjects/SoyuzOrbit/core/components.py#L625).

### Физический смысл

Это не "идеальный массив значений", а эквивалент источника Теvenin:

```text
идеальная ЭДС e(t) последовательно с внутренним сопротивлением R_s
```

В этой схеме:

- `peak_voltage_v = 1.0`
- `internal_resistance_ohm = 0.2`

### Как берется `e(t)`

Из аудиофайла выбирается канал, затем в момент времени `t` значение отсчитывается с линейной интерполяцией между соседними сэмплами:

```text
x(t) = x[n] + (x[n+1] - x[n]) * frac
e(t) = V_dc + V_peak * x(t)
```

См. выбор сэмпла в [components.py](/Users/arturadamov/PycharmProjects/SoyuzOrbit/core/components.py#L710) и формирование ЭДС в [components.py](/Users/arturadamov/PycharmProjects/SoyuzOrbit/core/components.py#L746).

### Закон тока

Для двухполюсного эквивалента ток считается как:

```text
I = (V_branch - e(t)) / R_s
```

или в форме проводимости:

```text
G = 1 / R_s
I = G * V_branch - G * e(t)
```

См. [components.py](/Users/arturadamov/PycharmProjects/SoyuzOrbit/core/components.py#L750).

### Что это значит для схемы

Источник не бесконечно жесткий:

- при больших токах напряжение на узле уже не обязано точно совпадать с идеальным аудиосэмплом;
- нелинейная сеть после него может реально "тянуть" ток у источника.

## 4.2. `C_HP`: Входной Конденсатор

См. [components.py](/Users/arturadamov/PycharmProjects/SoyuzOrbit/core/components.py#L192).

### Физический смысл

Это реальный конденсатор с:

- емкостью `C`;
- ESR;
- утечкой;
- условным breakdown-режимом;
- дискретной динамикой через companion-модель.

В схеме:

- `C_HP = 100 nF`

### Непрерывный закон

Для идеального конденсатора:

```text
I_C = C * dV/dt
Q = C * V
```

### Дискретная модель в проекте

В коде используется conductance-companion:

```text
G_cap ~ C / dt
I = G_cap * V + I_eq
```

См. [components.py](/Users/arturadamov/PycharmProjects/SoyuzOrbit/core/components.py#L219).

То есть на шаге `dt` конденсатор превращается в:

- эквивалентную проводимость;
- эквивалентный источник истории.

### Роль именно в `megaphone`

`C_HP` стоит последовательно, а после него узел `J_HP` тянется к земле через `R_HP_GND`.

Это образует high-pass:

```text
f_c ~ 1 / (2 * pi * R * C)
```

При грубой оценке:

```text
R = 1800 Ohm
C = 100 nF
f_c ~ 884 Hz
```

То есть весь низ ниже примерно `0.9 kHz` заметно режется. Это и есть главная причина, почему схема звучит "узко" и "по-мегафонному".

## 4.3. `R_HP_GND`: Резистор После Входного Конденсатора

См. [components.py](/Users/arturadamov/PycharmProjects/SoyuzOrbit/core/components.py#L42).

### Закон

Обычный закон Ома:

```text
I = V / R(T)
```

где в проекте сопротивление еще может зависеть от температуры:

```text
R(T) = R_actual * (1 + alpha * (T - T_ref))
```

См. [components.py](/Users/arturadamov/PycharmProjects/SoyuzOrbit/core/components.py#L67).

### Роль в схеме

Он задает путь току на землю после `C_HP`.

Без него:

- high-pass в таком виде не сформировался бы;
- узел после `C_HP` был бы плохо определен по постоянной составляющей.

## 4.4. `R_DRIVE`: Последовательный Резистор Перед Клиппером

Это тоже `RealResistor`, см. [components.py](/Users/arturadamov/PycharmProjects/SoyuzOrbit/core/components.py#L42).

### Физическая роль

Он делает три вещи:

1. ограничивает ток в узел `J_CLIP`;
2. задает мягкость перегруза;
3. вместе с `C_LP` задает верхнюю границу полосы.

### Почему он важен

Если бы `R_DRIVE` был слишком мал:

- диоды и варистор начали бы жестко резать сигнал;
- wave-shape стал бы гораздо более квадратным;
- возможны были бы более тяжелые численные режимы.

При `680 Ohm` клиппирование остается грубым, но не полностью "кирпичным".

## 4.5. `V_CLIP`: Varistor

См. [components.py](/Users/arturadamov/PycharmProjects/SoyuzOrbit/core/components.py#L1088).

### Физический смысл

Это симметричный нелинейный ограничитель:

- при малом напряжении течет только маленький ток утечки;
- при превышении порога проводимость резко растет.

В этой схеме:

- `clamp_voltage_v = 0.76 V`
- `dynamic_resistance_ohm = 10`
- `nonlinear_exponent = 2.7`

### Закон

Ниже порога:

```text
I ~ G_leak * V
```

где:

```text
G_leak = I_leak / V_clamp
```

Выше порога по модулю:

```text
excess = |V| - V_clamp
ratio = excess / V_clamp
boost = 1 + ratio^n
I = sign(V) * (I_leak + excess * boost / R_dyn)
```

См. [components.py](/Users/arturadamov/PycharmProjects/SoyuzOrbit/core/components.py#L1111).

### Что он делает в `megaphone`

Это симметричная "страховочная" клемма по обеим полуволнам. Но в этой схеме он не единственный ограничитель:

- раньше него вступают диоды `D_POS` и `D_NEG`;
- поэтому основную асимметрию задают именно диоды;
- `V_CLIP` добирает уже более крупные выбросы и удерживает узел в более узком диапазоне.

## 4.6. `D_POS`: Диод Положительной Полуволны

См. модель в [components.py](/Users/arturadamov/PycharmProjects/SoyuzOrbit/core/components.py#L859), а подключение в [audio_speech_megaphone_distortion.json](/Users/arturadamov/PycharmProjects/SoyuzOrbit/examples/audio_speech_megaphone_distortion.json#L245).

### Ориентация в схеме

`D_POS` подключен так:

- анод на `J_CLIP`;
- катод на землю.

Значит, он начинает проводить, когда узел `J_CLIP` становится положительным относительно земли.

### Физический закон

В основе лежит уравнение Шокли:

```text
I_D = I_S * (exp(V / (n * V_T)) - 1)
```

где:

```text
V_T = kT / q
```

См. `thermal_voltage` в [physics.py](/Users/arturadamov/PycharmProjects/SoyuzOrbit/core/physics.py#L50).

### Что добавлено сверх "учебного" диода

В этой модели есть не только голая экспонента, но и:

- built-in potential;
- ширина обедненного слоя;
- физическая junction capacitance;
- recombination current;
- shunt path;
- breakdown-ветка;
- diffusion conductance;
- reverse recovery через stored charge.

Это видно в [components.py](/Users/arturadamov/PycharmProjects/SoyuzOrbit/core/components.py#L920), [components.py](/Users/arturadamov/PycharmProjects/SoyuzOrbit/core/components.py#L937), [components.py](/Users/arturadamov/PycharmProjects/SoyuzOrbit/core/components.py#L945), [components.py](/Users/arturadamov/PycharmProjects/SoyuzOrbit/core/components.py#L966), [components.py](/Users/arturadamov/PycharmProjects/SoyuzOrbit/core/components.py#L980).

### Роль в схеме

У `D_POS` задан:

- `forward_drop_v = 0.32 V`

Это низкий порог. Следовательно, положительная полуволна начинает ограничиваться раньше.

Именно поэтому на твоем zoom-графике положительные пики выходного сигнала заметно ниже, чем отрицательные по модулю.

## 4.7. `D_NEG`: Диод Отрицательной Полуволны

Подключение см. в [audio_speech_megaphone_distortion.json](/Users/arturadamov/PycharmProjects/SoyuzOrbit/examples/audio_speech_megaphone_distortion.json#L267).

### Ориентация

У этого диода:

- анод на земле;
- катод на `J_CLIP`.

Значит, он начинает проводить, когда `J_CLIP` уходит достаточно глубоко в отрицательную область.

### Порог

В схеме:

- `forward_drop_v = 0.52 V`

То есть отрицательная полуволна режется позже, чем положительная.

### Следствие

Асимметрия заложена намеренно:

```text
+ полуволна клиппируется раньше
- полуволна клиппируется позже
```

Это и дает "металлический", несимметричный тембр, который хорошо совпадает с тем, что видно на твоем zoom-графике и на `input -> output`.

## 4.8. `C_LP`: Верхний Шунтирующий Конденсатор

Это тоже `RealCapacitor`, см. [components.py](/Users/arturadamov/PycharmProjects/SoyuzOrbit/core/components.py#L192).

### Физическая роль

Он сидит на узле `J_CLIP` и шунтирует быстрые составляющие на землю.

Поэтому:

- очень быстрые пики и резкие фронты частично сглаживаются;
- верхняя часть спектра не разлетается бесконтрольно после клиппинга;
- звук остается "громкоговорительным", а не уходит в совсем хрупкий фузз.

### Приближенная частота

Если грубо смотреть только на `R_DRIVE` и `C_LP`:

```text
R ~ 680 Ohm
C = 68 nF
f_c ~ 1 / (2 * pi * R * C) ~ 3440 Hz
```

Это оценка, не точная формула для всей нелинейной схемы, но как инженерный ориентир она полезна.

## 4.9. `R_LEAK`: Резистор Утечки На Клип-Узле

Это линейный резистор `33 kOhm`, см. [audio_speech_megaphone_distortion.json](/Users/arturadamov/PycharmProjects/SoyuzOrbit/examples/audio_speech_megaphone_distortion.json#L130).

### Что он делает

- не дает узлу `J_CLIP` висеть в воздухе;
- задает медленную утечку к земле;
- стабилизирует средний режим узла;
- вместе с реактивными элементами влияет на временную память эффекта.

## 4.10. `OUT_MEGA`: Audio Sink

См. [components.py](/Users/arturadamov/PycharmProjects/SoyuzOrbit/core/components.py#L800).

### Электрическая часть

Это высокоомная нагрузка:

```text
I = (G_res + G_cap) * V + I_eq
```

В этой схеме:

- `input_resistance_ohm = 1e9`
- `input_capacitance_f = 0`

Значит, электрически он почти не грузит узел.

### Что он делает как измерительный элемент

После получения напряжения он может:

1. вычесть медленно меняющуюся среднюю составляющую, если `dc_block = true`;
2. умножить результат на `output_gain`.

В этой схеме:

- `dc_block = true`
- `output_gain = 4.5`

Следовательно:

```text
captured_v = 4.5 * (V_node - running_mean)
```

См. [components.py](/Users/arturadamov/PycharmProjects/SoyuzOrbit/core/components.py#L835).

### Важная оговорка

`OUT_MEGA.captured_v` не является "напряжением в самой схеме". Это уже пост-обработанный измерительный сигнал:

- без DC;
- с масштабированием.

Поэтому на аудио-графиках ты смотришь не чистый узловой `reading_v`, а именно сигнал, подготовленный к сохранению в аудиофайл.

## 5. Схема Целиком Как Инженерная Функция

Если грубо свернуть весь тракт:

```text
input
-> high-pass
-> drive resistor
-> asymmetric clipper
-> mild top smoothing
-> DC removal + output gain
-> output
```

То есть физический смысл схемы такой:

- низ вырезать;
- середину оставить;
- пики сжать;
- сделать положительную и отрицательную полуволны разными;
- слегка прибрать резкие ВЧ-осколки после клиппинга.

## 6.1. График `Аудио: увеличенный фрагмент волны`

Что видно:

- входной сигнал `Input:SRC_AUDIO` имеет больший размах;
- выход `Output:OUT_MEGA` уже заметно поджат;
- положительные пики на выходе ограничены сильнее;
- отрицательные пики по модулю проходят глубже;
- форма выхода заметно менее синусоидальна и менее симметрична;
- есть фазовый сдвиг и сглаживание между входом и выходом.

Что из этого следует:

1. Схема точно нелинейна.
Если бы это был просто линейный фильтр, форма оставалась бы похожей на входную с масштабированием и фазовым сдвигом. Здесь видна именно деформация пиков.

2. Ограничение асимметрично.
Положительная полуволна режется раньше, чем отрицательная. Это прямо соответствует номиналам:

- `D_POS.forward_drop_v = 0.32`
- `D_NEG.forward_drop_v = 0.52`

3. Есть реактивная память.
Выход не просто "обрублен", а немного запаздывает и сглаживается. Это работа `C_HP` и `C_LP`.

4. Это уже похоже именно на "мегафон", а не на обычный hard clip.
Потому что виден не только перегруз, но и фильтрация полосы.

## 6.2. График `Аудио: спектр входа и выхода`

На присланной картинке виден диапазон примерно до `500 Hz`. Это важно: по ней можно уверенно судить про низ, но нельзя полноценно судить про всю среднюю и верхнюю часть полосы.

Что видно в этом диапазоне:

- выходной спектр сильно ниже входного на очень низких частотах;
- ближе к нескольким сотням герц разница уменьшается;
- значит, самый низ действительно подавляется.

Это физически согласуется с high-pass звеном:

```text
C_HP = 100 nF
R_HP_GND = 1800 Ohm
f_c ~ 884 Hz
```

Что из этого следует:

1. Схема убирает басовую основу речи.
Именно поэтому голос становится "тоньше", "уже" и "радиофицированнее".

2. Самый низ не просто ослаблен, а системно вырезан.
То есть это не случайная потеря уровня, а целенаправленное полосовое формирование.

3. По этой конкретной картинке нельзя до конца оценить верхнюю границу полосы.
Для полного вывода по "мегафонной" полосе лучше смотреть спектр хотя бы до `4-6 kHz`.

## 6.3. График `Аудио: вход -> выход`

Это самый информативный график для нелинейности.

Если бы схема была:

- идеальным повторителем, точки лежали бы на диагонали `y = x`;
- линейным усилителем с коэффициентом `k`, точки легли бы на тонкую прямую `y = kx`;
- статическим симметричным клиппером, облако было бы симметрично и с плоскими краями.

Что видно у тебя:

- облако сильно сжато относительно диагонали;
- наклон меньше 1;
- облако толстое, а не тонкое;
- есть асимметрия между положительной и отрицательной частью;
- около нуля поведение ближе к линейному, на больших амплитудах сильнее отклоняется.

Что это означает:

1. Есть компрессия амплитуды.
Выход растет медленнее, чем вход. Значит, пиковые участки реально подрезаются.

2. Нелинейность несимметрична.
Это опять согласуется с разными порогами `D_POS` и `D_NEG`.

3. Схема обладает памятью.
Если бы преобразование было чисто мгновенным `y = f(x)`, облако было бы более тонким. Толщина облака означает, что один и тот же `input` дает разный `output` в зависимости от предыстории сигнала. Это работа реактивных элементов, прежде всего `C_HP` и `C_LP`.

4. Это не просто EQ.
EQ дал бы почти линейное облако. Здесь видно именно динамически-нелинейное преобразование.

## 7. Что Вообще Можно Выводить Из Таких Графиков

По этим трем графикам уже можно проводить вполне содержательный анализ.

### 7.1. Анализ Фильтрации

По спектру можно оценить:

- насколько вырезан низ;
- где начинается подъем полезной полосы;
- насколько равномерно проходит середина;
- не слишком ли задавлены высокие.

Для `megaphone` главный вопрос:

- "осталась ли энергия речевой середины при сильном подавлении низа?"

### 7.2. Анализ Нелинейности

По `input -> output` можно оценить:

- порог начала компрессии;
- силу поджатия;
- симметрична ли характеристика;
- есть ли память.

Это особенно полезно для подстройки:

- `R_DRIVE`
- `V_CLIP.clamp_voltage_v`
- `D_POS.forward_drop_v`
- `D_NEG.forward_drop_v`

### 7.3. Анализ Формы Волны

По zoom-графику можно смотреть:

- где именно режутся пики;
- насколько смещена фаза;
- насколько различаются полуволны;
- не превращается ли сигнал в слишком "кирпичный" и не убивает ли речь.

### 7.4. Анализ Разборчивости Речи

Косвенно по этим графикам можно судить и о разборчивости:

- если низ вырезан, но середина оставлена, речь обычно остается понятной;
- если клиппинг слишком силен и облако сильно сплющено, согласные начинают разрушаться;
- если реактивная память слишком велика, слоги размазываются.

По присланным графикам твой `megaphone` сейчас выглядит как умеренно агрессивный, но не полностью разрушающий речь.

## 8. Главный Вывод По Этой Схеме

Физически это не "одна магическая коробка", а вполне читаемая комбинация:

```text
Thevenin-аудиоисточник
+ RC high-pass
+ ограничение тока драйв-резистором
+ асимметричное диодное клиппирование
+ симметричный backup-clamp на varistor
+ RC-приглаживание верха
+ DC-block и масштабирование на выходе
```

Именно поэтому:

- на waveform видно асимметричную деформацию;
- на спектре видно подавление низа;
- на transfer-graph видно динамическую нелинейность с памятью.

То есть схема реально считается физически содержательно на уровне circuit simulation, а не как абстрактный DSP-эффект с произвольным названием.

## 9. Что Имеет Смысл Крутить, Если Хочешь Изменить Характер `Megaphone`

Чтобы сделать звук жестче:

- уменьшать `R_DRIVE`
- уменьшать `V_CLIP.clamp_voltage_v`
- уменьшать `D_NEG.forward_drop_v`

Чтобы сделать звук разборчивее:

- поднимать `V_CLIP.clamp_voltage_v`
- увеличивать `R_DRIVE`
- уменьшать `output_gain`

Чтобы сделать звук еще "телефоннее":

- уменьшать `C_HP`
- уменьшать `R_HP_GND`
- тем самым поднимать нижнюю границу полосы

Чтобы сделать меньше шершавости на верхах:

- увеличивать `C_LP`

## 10. Практическая Оговорка

Хотя физическая логика схемы корректна, надо честно разделять два уровня:

- электрическая схема тут считается физически осмысленно;
- но итоговое восприятие "мегафона" человеком зависит еще и от акустики, динамика, корпуса, комнаты и слуховой психоакустики, а это здесь не моделируется.

Поэтому корректнее всего формулировать так:

- проект правильно считает электрическое преобразование аудиосигнала этой схемой;
- а "насколько это похоже именно на конкретный реальный мегафон" уже зависит от того, насколько удачно выбраны номиналы.
