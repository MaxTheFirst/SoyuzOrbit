# Audio Component Physics

Этот файл описывает не аудио-пресеты, а базовые элементы ядра, на которых строятся аудио-схемы:

- `AudioFileSource`
- `AudioSink`
- `SchockleyDiode`
- `Varistor` / `MOV`

Описание ниже привязано к реальной реализации проекта, а не к абстрактной электронике вообще.

## 1. Общая вычислительная модель

## 1.1. Что решает симулятор

В основе лежит узловой расчет по напряжениям.

На каждом временном шаге решатель ищет такие напряжения узлов `V`, при которых выполняется закон Кирхгофа по токам:

```text
для каждого узла: sum(I_k(V, t, dt)) = 0
```

То есть суммарный ток, который все подключенные компоненты вносят в узел, должен быть равен нулю.

Это собирается в нелинейную систему:

```text
F(V) = 0
```

и дальше решается итерационно.

## 1.2. Как представлен двухвыводный элемент

Все четыре интересующих нас элемента являются `TwoTerminalComponent`.

Для двухвыводного элемента задается:

```text
Vbranch = V(positive) - V(negative)
Ibranch = I(Vbranch, t, dt)
Gbranch = dI/dV  или его эквивалентная линейзация
```

После этого элемент штампуется в систему как:

```text
currents = [ Ibranch, -Ibranch ]

jacobian =
[
  [ Gbranch, -Gbranch ],
  [ -Gbranch, Gbranch ]
]
```

Физический смысл:

- ток из положительного вывода входит в уравнение со знаком `+`;
- ток из отрицательного вывода входит со знаком `-`;
- это прямая реализация KCL для ветви между двумя узлами.

## 1.3. Как идет решение по времени

На каждом шаге:

1. Все компоненты получают `time_s` и `dt_s`.
2. Из их локальных моделей собираются суммарные `residual` и `jacobian`.
3. Сначала запускается локальная Newton-подобная итерация.
4. Если она не сходится, включается `scipy.optimize.root(..., method="hybr")`.
5. После решения шага компоненты коммитят внутреннее состояние: прошлые напряжения, прошлые токи, накопленный заряд, температуру и так далее.

Это важно:

- аудио здесь не “просто массив чисел”;
- каждый сэмпл реально проходит через электрическую схему в transient-режиме.

## 1.4. Численные оговорки

В модели есть стабилизирующие численные элементы:

- `GMIN = 1e-9 S`
- ограничение экспоненты через `safe_exp`
- ограничение шага Newton
- companion-модели для емкостей и других memory-эффектов

`GMIN` нужен не как физический закон, а как численный пол в матрице проводимостей.

## 1.5. Тепловая модель

У `Component` есть две температуры:

- `temperature_c` — внутренняя / junction-like
- `surface_temperature_c` — поверхностная

Тепло считается двухузловой моделью:

```text
heat_to_surface = (Tjunction - Tsurface) / R_junction_surface

Tjunction += (Power - heat_to_surface) * dt / Cjunction

Tsurface += (heat_to_surface - (Tsurface - Tambient) / R_surface_ambient) * dt / Csurface
```

В коде это разбито на:

- `integrate_temperature(...)`
- `thermal_step(...)`

Для `Diode` и `Varistor` это реально используется.

Для `AudioFileSource` — нет, он не моделирует тепловой нагрев как физическое устройство вывода сигнала.

## 2. AudioFileSource

## 2.1. Что это физически

`AudioFileSource` — это не микрофон, не DAC и не полноценная акустическая модель.

Физически в рамках симулятора это:

- управляемый по времени источник напряжения;
- с внутренним последовательным сопротивлением;
- у которого закон изменения ЭДС берется из декодированного аудиофайла.

То есть это приближение вида:

```text
идеальный источник emf(t) + внутреннее сопротивление Rint
```

Именно поэтому он хорошо подходит как электрический вход в схему, но не моделирует акустический тракт целиком.

## 2.2. Цифровая часть перед физикой

Перед тем как источник начнет работать как электрический элемент, происходит цифровая подготовка сигнала:

- файл декодируется;
- при необходимости делается ресемплинг;
- при необходимости берется mono mix или конкретный канал;
- при необходимости сигнал нормализуется.

Это делает `load_audio_file(...)` и `AudioBuffer`.

`AudioBuffer` хранит:

- `sample_rate_hz`
- `channels`
- `samples`

Если `normalize = true`, весь массив делится на пиковое значение:

```text
samples_norm = samples / max(abs(samples))
```

Это не физика цепи, а входная нормализация данных перед электрическим расчетом.

## 2.3. Выбор канала

Поддерживаются режимы:

- `mono`
- `left`
- `right`
- явный индекс канала

Для `mono` берется среднее:

```text
mono[n] = mean(channels[n])
```

То есть при стерео-входе это обычный downmix, а не HRTF, не binaural и не psychoacoustics.

## 2.4. Как получается непрерывное значение между сэмплами

Симулятору нужен сигнал в произвольный момент времени `t`, а не только в целых индексах массива.

Поэтому используется линейная интерполяция:

```text
position = t * fs
left_index = floor(position)
ratio = position - left_index

s(t) = s[left_index] + (s[left_index + 1] - s[left_index]) * ratio
```

Это очень важный момент:

- источник не прыгает ступеньками между аудио-сэмплами;
- он создает кусочно-линейную аппроксимацию сигнала.

Физический смысл:

- это ближе к идеализированному интерполирующему ЦАП, чем к zero-order hold;
- но это все еще упрощение, без модели reconstruction filter.

## 2.5. Закон ЭДС

После выборки из аудио вводится масштаб и смещение:

```text
emf(t) = dc_offset_v + peak_voltage_v * sample_value(t)
```

Здесь:

- `sample_value(t)` обычно в диапазоне `[-1, 1]`
- `peak_voltage_v` задает электрическую амплитуду источника
- `dc_offset_v` добавляет постоянную составляющую

## 2.6. Закон тока в ветви

Дальше источник работает как Теvenin-эквивалент:

```text
I = (Vbranch - emf(t)) / Rint
G = 1 / Rint
```

В коде это записано как:

```text
current = conductance * voltage_v - conductance * instantaneous_emf_v
conductance = 1 / internal_resistance_ohm
```

Физический смысл:

- если напряжение на ветви равно ЭДС, ток нулевой;
- если схема “тянет” узел ниже ЭДС, источник начинает отдавать ток;
- если схема поднимает узел выше ЭДС, ток может пойти обратно в источник.

## 2.7. Что еще делает источник

У него есть режимы:

- `loop`
- `hold_last_value`
- `start_time_s`

Это уже логика воспроизведения:

- `loop = true` зацикливает буфер;
- `hold_last_value = true` после окончания оставляет последнее значение, а не ноль;
- `start_time_s` сдвигает начало проигрывания по времени симуляции.

## 2.8. Чего здесь физически нет

В `AudioFileSource` не моделируются:

- квантование реального DAC;
- zero-order hold;
- джиттер тактов;
- выходной reconstruction filter;
- выходной каскад реальной звуковой карты;
- нелинейность драйвера, микрофона или предусилителя.

То есть это электрически удобный источник сигнала, а не полный аппаратный тракт.

## 3. AudioSink

## 3.1. Что это физически

`AudioSink` — это не динамик и не микрофон записи.

Физически это:

- измерительный порт;
- с входным сопротивлением;
- с опциональной входной емкостью;
- который дополнительно умеет сохранить напряжение в `captured_v`.

То есть это смесь:

- нагрузки на схему;
- измерительного прибора;
- цифрового экспортного шлюза из transient-расчета обратно в аудиофайл.

## 3.2. Электрическая модель входа

На входе у `AudioSink` есть:

- резистивная проводимость `1 / Rin`
- опциональная входная емкость `Cin`

Это значит, что ток складывается из двух частей:

```text
Ires = V / Rin
Icap = C * dV/dt
```

В дискретной companion-модели:

```text
Gres = 1 / Rin
Gcap = Cin / dt
Ieq = -Gcap * Vprev

I = (Gres + Gcap) * V + Ieq
```

Это стандартная линейная дискретизация емкости.

## 3.3. Что именно сохраняется

После решения шага `AudioSink` обновляет:

- `reading_v` — текущее напряжение на входе
- `input_current_a` — ток нагрузки
- `captured_v` — то, что потом идет в экспорт аудио

Если `dc_block = false`:

```text
captured_v = output_gain * V
```

Если `dc_block = true`:

```text
captured_v = output_gain * (V - running_mean)
```

## 3.4. Что такое `running_mean`

Это однополюсный цифровой high-pass через вычитание медленного среднего:

```text
alpha = dt / (0.02 + dt)
running_mean += alpha * (V - running_mean)
captured = V - running_mean
```

Физический смысл:

- это не физический конденсатор на входе;
- это программный DC-block на экспортируемом сигнале.

Характерное время:

```text
tau ≈ 0.02 s
fc ≈ 1 / (2 * pi * tau) ≈ 8 Hz
```

То есть медленный оффсет убирается, а полезное аудио почти не затрагивается.

## 3.5. Как из него получается WAV/MP3

После симуляции `audio_buffer_from_simulation_result(...)` берет массив:

```text
observables[component_name]["captured_v"]
```

и считает частоту дискретизации как:

```text
sample_rate_hz = round(1 / dt_s)
```

Потом это превращается в `AudioBuffer`, а затем `save_audio_file(...)` пишет результат через `ffmpeg` или WAV fallback.

Важно:

- `AudioSink` не моделирует акустику динамика;
- он только считывает электрическое напряжение и экспортирует его как цифровой моно-буфер.

## 3.6. Чего здесь физически нет

В `AudioSink` не моделируются:

- катушка и мембрана динамика;
- электромеханическое преобразование;
- акустический объем, корпус, воздух, ухо;
- psychoacoustic loudness.

То есть это именно электрический probe/export, а не “виртуальная колонка”.

## 4. SchockleyDiode

## 4.1. Что это физически

`SchockleyDiode` моделирует p-n переход.

Физические эффекты, которые здесь реально учтены:

- прямой экспоненциальный ток p-n перехода;
- рекомбинационно-генерационный ток;
- барьерная / junction capacitance;
- diffusion / transit-time эффект;
- avalanche-like пробой при обратном перенапряжении;
- reverse recovery через stored charge;
- температурная зависимость.

Это уже заметно богаче, чем “идеальный диод + постоянное падение”.

## 4.2. Тепловое напряжение

Базовая величина:

```text
Vt = kT / q
```

где:

- `k` — постоянная Больцмана
- `T` — температура в Кельвинах
- `q` — заряд электрона

Именно через `Vt` зависит крутизна экспоненты диода.

## 4.3. Built-in potential

Встроенный потенциал перехода:

```text
Vbi = Vt * ln( Na * Nd / ni^2 )
```

где:

- `Na` — концентрация акцепторов
- `Nd` — концентрация доноров
- `ni` — собственная концентрация носителей

Эта величина нужна дальше для depletion width и электрического поля.

## 4.4. Ширина обедненного слоя

Используется формула:

```text
W = sqrt( 2 * eps * Vdep * (1/Na + 1/Nd) / q )
```

где:

- `eps = relative_permittivity * epsilon_0`
- `Vdep` — эффективный depletion potential

Это дает физически осмысленную зависимость ширины обеднения от напряжения.

## 4.5. Пиковое поле

После этого считается:

```text
Epeak = 2 * (Vbi - V) / W
```

Это диагностическая величина, показывающая напряженность поля в переходе.

## 4.6. Junction capacitance

Емкость перехода считается двумя способами и потом смешивается:

1. Физическая плоская модель:

```text
Cphys = eps * Area / W
```

2. Compact-приближение через `junction_capacitance(...)`

Итог:

```text
Cj = 0.35 * Ccompact + 0.65 * Cphys
```

То есть модель опирается и на геометрию, и на привычную для compact-model зависимость.

## 4.7. Прямой ток p-n перехода

Основная forward-ветка:

```text
If = Is_eff * ( exp(V / (n * Vt)) - 1 )
```

где:

- `Is_eff` — эффективный saturation current
- `n` — emission coefficient

Но `Is_eff` здесь не постоянный: он масштабируется с температурой и параметром `forward_drop_v`.

То есть в модели есть температурная подстройка прямой ветви.

## 4.8. Рекомбинационный ток

Дополнительно есть отдельный recombination/generation contribution:

```text
Irec ~ q * Area * ni * W / (2 * tau) * (exp(V / (2Vt)) - 1)
```

Здесь:

- `tau` — carrier_lifetime_s
- `W` — depletion width

Это добавляет более физичный переходный режим около области малых токов.

## 4.9. Шунтирующая утечка

Есть и простая шунтирующая проводимость:

```text
Ish = V / Rsh
```

Это нужна и как физическая утечка, и как численная стабилизация.

## 4.10. Пробой

Если напряжение уходит сильнее, чем `-breakdown_voltage_v`, включается soft avalanche-like режим:

```text
overdrive = -(V + Vbr)
Gbr = 1 / (4 * avalanche_softness)
Ibr = -Gbr * overdrive * (1 + overdrive / (avalanche_softness + overdrive))
```

Это не full avalanche physics, но уже не просто жесткий “если пробой, то короткое”.

## 4.11. Динамические токи: емкость, diffusion, reverse recovery

Статическая часть диода — это только половина модели.

В `branch_current(...)` добавляются еще три динамических вклада.

### 4.11.1. Junction capacitance companion

```text
Gcap = Cj / dt
Ieq = -Gcap * Vprev
Icap = Gcap * V + Ieq
```

Это дискретная емкость перехода.

### 4.11.2. Diffusion / transit-time

Используется `transit_time_s`.

Вклад проводимости:

```text
Gdiff = transit_time * dIf/dV / dt
```

Вклад тока:

```text
Idiff = transit_time * (If_now - If_prev) / dt
```

Физический смысл:

- при быстром изменении forward current диод показывает память по заряду носителей;
- это важно в быстрых нелинейных переходах и аудио-клиппинге тоже.

### 4.11.3. Reverse recovery

Есть stored charge:

```text
Irr = -Qstored / tau_rr
```

А сам заряд обновляется как:

```text
Qtarget = transit_time * If_forward
Qstored += alpha * (Qtarget - Qstored)
alpha = dt / (tau_rr + dt)
```

При обратном смещении заряд дополнительно экспоненциально спадает:

```text
Qstored *= exp(-dt / tau_rr)
```

Это и есть модель reverse recovery.

## 4.12. Итоговый закон тока диода

Ветвевой ток в модели:

```text
Idiodelaw =
  Istatic
  + Icap
  + Idiff
  + Irr
```

А эквивалентная проводимость:

```text
Gdiodelaw =
  Gstatic
  + Gcap
  + Gdiff
  + GMIN
```

То есть решатель видит уже не одну экспоненту, а целый набор физических и квазифизических вкладов.

## 4.13. Тепло диода

После коммита считается статический ток и мощность:

```text
P ≈ |V * Istatic|
```

Потом эта мощность идет в тепловую модель компонента.

Это значит, что температура может менять `Vt`, а через нее и саму I-V характеристику.

## 4.14. Что здесь не моделируется

Несмотря на богатую модель, здесь все еще нет:

- полного SPICE-эквивалента конкретного диода из даташита;
- self-heating на уровне сложной распределенной геометрии;
- шума, flicker noise, shot noise;
- детальной лавинной статистики;
- паразитных выводных индуктивностей корпуса как отдельного элемента.

## 5. Varistor / MOV

## 5.1. Что это физически

MOV — metal-oxide varistor, обычно на основе ZnO.

Физически это:

- симметричный по полярности нелинейный резистор;
- почти изолятор на малых напряжениях;
- резко проводящий элемент выше некоторого порога.

В аудио-схемах проекта он используется как:

- мягкий symmetric clipper;
- saturator;
- ограничитель пиков.

## 5.2. Что моделируется

В отличие от диода, MOV здесь не пытается детально моделировать микроструктуру зерен ZnO.

Вместо этого используется симметричная нелинейная I-V модель с параметрами:

- `clamp_voltage_v`
- `dynamic_resistance_ohm`
- `leakage_current_a`
- `nonlinear_exponent`

## 5.3. Утечка ниже порога

Ниже порога MOV ведет себя как слабая линейная утечка:

```text
Gleak = Ileak / Vclamp
I = Gleak * V
```

Это дает малую проводимость еще до начала активного clamp.

## 5.4. Режим выше порога

Если:

```text
|V| > Vclamp
```

то вводятся:

```text
excess = |V| - Vclamp
ratio = excess / Vclamp
boost = 1 + ratio^alpha
```

где `alpha = nonlinear_exponent`.

После этого ток:

```text
I = sign(V) * ( Ileak + excess * boost / Rdyn )
```

А проводимость:

```text
G = Gleak + [ boost + alpha * excess * ratio^(alpha - 1) / Vclamp ] / Rdyn
```

Физический смысл параметров:

- `clamp_voltage_v` — точка колена;
- `dynamic_resistance_ohm` — насколько круто MOV проводит после включения;
- `nonlinear_exponent` — насколько резко появляется эта проводимость;
- `leakage_current_a` — слабая проводимость ниже колена.

## 5.5. Почему модель симметрична

Ветвь зависит от `abs(V)` и потом домножается на `sign(V)`.

То есть:

- положительная и отрицательная полуволна ограничиваются одинаково;
- это важно для аудио, когда нужен symmetric soft clipping.

Именно поэтому MOV хорошо работает как более “мягкий” saturator по сравнению с парой диодов.

## 5.6. Тепло MOV

После коммита используется:

```text
P = |V * I|
```

и дальше эта мощность идет в общую тепловую модель компонента.

Это особенно полезно в защитных схемах и в более длинных transient-задачах.

## 5.7. Что здесь не моделируется

В текущей MOV-модели нет:

- паразитной емкости MOV;
- aging после импульсных перегрузок;
- деградации колена от энергии импульса;
- гистерезиса;
- частотной зависимости, кроме той, что возникает через сам transient схемы вокруг него.

То есть это хорошая симметричная nonlinear I-V модель, но не surge-datasheet simulator.

## 6. Как эти элементы работают вместе в аудио-схемах

Типичный сценарий такой:

1. `AudioFileSource` задает во времени ЭДС `emf(t)`.
2. Решатель на каждом шаге находит узловые напряжения схемы.
3. `Diode` и `MOV` вносят в узлы нелинейные токи и свои динамические эффекты.
4. `AudioSink` нагружает узел, измеряет напряжение и пишет его в `captured_v`.
5. `audio_buffer_from_simulation_result(...)` собирает весь временной ряд в цифровой аудиобуфер.

Именно поэтому:

- band-pass схемы реально отфильтровывают электрический сигнал;
- clipper-схемы реально искажают форму волны через нелинейную I-V характеристику;
- envelope- и hold-схемы реально используют память по заряду и companion-модели.

## 7. Граница между физикой и интерфейсом

Здесь очень важно не смешивать три уровня.

### 7.1. Что является именно физикой цепи

- KCL по узлам
- токи через ветви
- conductance / jacobian stamping
- емкостные и зарядовые companion-модели
- нелинейные I-V характеристики
- тепловая обратная связь

### 7.2. Что является цифровым интерфейсом

- декодирование `mp3/wav/flac/...`
- ресемплинг файла
- выбор канала
- нормализация входа
- экспорт `captured_v` в `wav/mp3`

### 7.3. Что в проекте пока не моделируется как полноценная физика

- микрофон как электромеханический преобразователь;
- акустика комнаты;
- громкоговоритель как механическая система;
- psychoacoustic восприятие;
- реальный DAC/ADC во всех деталях.

## 8. Короткий итог по четырем элементам

`AudioFileSource`:

- это Теvenin-источник напряжения, управляемый аудиофайлом во времени.

`AudioSink`:

- это нагрузка + измерительный порт + экспортный шлюз, а не виртуальная колонка.

`SchockleyDiode`:

- это богатая p-n модель с экспонентой, рекомбинацией, capacitance, diffusion и reverse recovery.

`Varistor / MOV`:

- это симметричный нелинейный резистор с коленом, мягким clamp и тепловой мощностью.

Если нужно, следующим шагом можно сделать еще один такой же технический файл отдельно про:

- `MOSFET`
- `Capacitor`
- `Inductor`
- `OpAmp`

потому что именно на них строятся почти все более сложные аудио-эффекты проекта.
